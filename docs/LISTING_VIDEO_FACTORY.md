# Listing Video Factory

Turns static real-estate listing photographs into polished property-tour
videos for TikTok / Reels / Shorts (9:16), YouTube & listing pages (16:9),
and square feed posts — as a fully integrated subapp of the AI Business
Factory. Open it at **`/apps/listing-video-factory`** (also the 🎬 card on
the My Apps home).

## How it works

1. **Create a project** (name + address are enough to start; drafts autosave
   on every action).
2. **Upload photos** — drag-and-drop or browse (JPG/PNG/WEBP, ≤50 per
   project). Large photos are downscaled in the browser before upload so
   serverless body limits never bite. Paste-from-URL import is also
   supported (https-only, private hosts blocked). Duplicates are detected by
   content hash. Bytes live in the platform `Asset` table via the standard
   storage driver (local FS / Postgres-blob on Vercel / S3) and are served
   through the org-scoped `/api/assets/raw` streamer.
3. **Organize** — drag into tour order, or click *Apply recommended tour
   order* (exterior hero → living → kitchen → bedrooms → outdoor →
   amenities → floor plan, with a closing hero shot). Per photo: room label,
   type, factual note, exclude, cover, *virtually staged* / *AI-enhanced*
   flags.
4. **Property details** — all facts are optional except the address; the
   script generator is only allowed to use what you enter here plus photo
   labels/notes. A rights-confirmation checkbox is required before
   rendering.
5. **Style & format** — four data-driven templates (Luxury Cinematic, Fast
   Social, Clean Professional, No-Narration Showcase) × three formats ×
   toggles (voice-over, captions, music, price/address cards, agent outro).
   Templates are data in `packages/workflows/src/listing-factory/templates.ts`
   — adding one is adding an entry, not a new composition.
6. **Script** — generated by the `lvf-script-agent` through the platform
   agent runner (Claude when `ANTHROPIC_API_KEY` is set, deterministic
   schema-aware mock otherwise). One scene per photo, every line editable.
   A deterministic validator checks every version (generated or edited) for
   **fair-housing language** (buyer-profile phrasing, protected classes,
   safety/steering claims) and **unsupported claims** (renovations, views,
   square footage, "walking distance"… that the entered facts don't back
   up) and shows warnings inline before render.
7. **Render** — *preview* (fast, half-res, watermarked) or *final*. Renders
   run through the workflow engine — BullMQ background jobs in queue mode,
   per-step serverless invocations on Vercel inline mode — never inside a
   request. Two steps:
   - `listing_factory_prepare`: per-scene TTS with SHA-based reuse (an
     unchanged line is never paid for twice).
   - `listing_factory_assemble`: deterministic motion (Ken Burns zooms +
     pans per template), template transitions via `xfade`, client-rasterized
     text overlays, a synthesized royalty-free music bed with sidechain
     voice-ducking, H.264 output.
8. **Download** — MP4, narration captions (`.srt`), a generation report
   (scene list, timings, disclosures, providers), plus an agent-written
   social package (TikTok/Instagram captions, YouTube title + description,
   hashtags, cover text) with copy buttons.

### Typography without server fonts

The bundled ffmpeg has no `drawtext`, so **all on-video text (captions,
facts card, agent outro, preview watermark) is rasterized in the browser
with canvas at render time** and uploaded as full-frame transparent PNGs
that ffmpeg composites with time-windowed `overlay` filters. Renders
triggered outside a browser (e.g. the sample script) simply omit overlays.

## Data model

`ListingProject` (property JSON, format, style, options, script + warnings,
social package, rights confirmation) → `ListingPhoto` (organizer state;
bytes referenced via `Asset`) → `ListingRender` (immutable settings
snapshot, status, workflowRunId, video asset, cost). `BrandProfile` exists
for saved agent/brokerage branding (Phase 2 UI). Migration:
`20260727171632_listing_video_factory`. All rows are organization-scoped
and RBAC-checked (`workflows:execute` to mutate, `agents:execute` to
generate).

The module, its two agents, prompts, and the render workflow are installed
by an **idempotent runtime installer** (`ensureListingFactoryInstalled`)
the first time the subapp dashboard loads — existing deployments need no
manual seeding.

## Local development

```bash
pnpm infra:up && pnpm db:migrate && pnpm db:seed
pnpm dev:web      # sign in as owner@factory.local / factory-dev-password
# open http://localhost:3000/apps/listing-video-factory
```

Headless end-to-end sample (placeholder photos → script → render → MP4):

```bash
OUT=/tmp/sample.mp4 pnpm --filter @bf/database exec tsx ../workflows/scripts/sample-listing-render.ts
```

## API keys

| Works without any keys | With `ANTHROPIC_API_KEY` | With `OPENAI_API_KEY` | With `ELEVENLABS_API_KEY` | With `HIGGSFIELD_*` or `PICSART_API_KEY` |
| --- | --- | --- | --- | --- |
| Whole flow end-to-end: mock script, silent voice-over track, full render with music, captions, downloads | Real fact-grounded scripts + social packages | Real narration (gpt-4o-mini-tts, ≈$12/1M chars) | Upgraded expressive voices | **AI walkthrough motion** (~$0.55/scene, final renders): each photo becomes a moving steadicam-style shot via image-to-video (Higgsfield preferred; Picsart GenAI image2video otherwise), with conservative preserve-the-property prompts and per-scene Ken Burns fallback |

Estimated cost per video with real providers: script + social ≈ $0.01–0.05
(Claude), narration ≈ $0.01–0.03 (about 800–2,500 characters) — roughly
**$0.02–0.08 per video**; rendering itself is free (ffmpeg). A $3 hard cost
limit guards every render run, on top of the org's daily/monthly limits.

## Adding an image-to-video (AI motion) provider

Implement `ImageMotionProvider` from `@bf/providers` (`media-picsart.ts`
documents the contract and the mandatory conservative-motion guardrails),
return it from `getImageMotionProvider()`, and gate usage on your env key.
AI motion must remain opt-in per scene, disclosed, and must fall back to
deterministic motion when output alters the property.

## Known limitations

- HEIC uploads are attempted via browser decode; unsupported browsers get a
  clear per-file error (convert to JPG first).
- Captions are burned in only when the render is started from the browser
  (see typography note); the `.srt` sidecar is always generated.
- On Vercel without S3, media bytes live in Postgres (`STORAGE_DRIVER=db`
  fallback) — fine for getting started, move to S3/R2 for volume.
- Renders cap at 20 scenes / 3 minutes; photos at 50 per project, 8MB each.
- No automatic social posting (by design) — provider interfaces exist,
  publishing stays manual until official auth flows are added.
